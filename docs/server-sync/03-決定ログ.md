## D-06 — 99店ミニ盤面のタイル画像は「信用ライフ」を表す（評価ではない）

- **日付**: 2026-08-06
- **決定者**: クライアント側（サーバー調整不要）
- **関連項目**: [SV-15](./01-プロトコル契約の差分.md#sv-15)、[D-01](#d-01--店の評価3段階緑黄赤は相対順位の表示とする)

### 決定

`Assets/Images/minitile/minitile_booth_life*` は他店の **`CreditLife`（信用ライフ）** をそのまま表す。区分は5つ。

| 区分 | 条件 | 見た目 |
|---|---|---|
| `Life3` / `Life2` / `Life1` | `Alive` かつ `CreditLife` = 3 / 2 / 1 | `minitile_booth_life3/2/1` |
| `JustEliminated` | `Alive == false` になってから3秒間（または `CreditLife <= 0` かつ生存扱い） | `minitile_booth_life0` |
| `Eliminated` | 上記の3秒経過後 | 屋台を非表示にし、順位を表示 |

評価3段階（`StoreVisualState`、D-01）とは**別の指標**であり、ミニ盤面のタイル画像には評価を反映しない。

### 背景

当初、ミニ盤面の5状態を「評価3以上/2/1」と評価ベースで検討していたが、`evalNormalized` は 0..1 のパーセンタイルで整数段階を持たないうえ、画像名が `life*` であることから信用ライフの表現が自然と判断した。

### 影響範囲

- `Unity/docs/.sdd/value-objects/06-sub-store-tile-state.md`（新規作成）
- `Unity/docs/.sdd/10-sub-store-board-view.md`（新規作成）
- 順位表示は [SV-15](./01-プロトコル契約の差分.md#sv-15) の確定待ち

## D-05 — たこ焼き台の生地マス数は評価で決まる（注文個数ではない）

- **日付**: 2026-08-06
- **決定者**: クライアント側（サーバー調整不要）
- **関連項目**: [D-02](#d-02--たこ焼き台は6列4行24穴の横長グリッド)（**該当部分を撤回**）、[SV-14](./01-プロトコル契約の差分.md#sv-14)

### 決定

生地を流しておく穴の数は、**評価3段階（`StoreEvalLevel`）**で決まる。

| `EvalLevel` | 生地マス数 |
|---|---|
| `Low` | 12（1〜2行目） |
| `Mid` | 18（1〜3行目） |
| `High` | 24（全マス） |

焼けた穴の数は `min(TypedWordCount, 生地マス数)` のまま変更しない。

**D-02 のうち「生地を流す穴の数は `min(orderCount, 24)`」の部分を撤回する。** グリッド形状（6列×4行＝24穴）と3状態（`Empty`/`Batter`/`Cooked`）は D-02 のまま有効。

### 背景

D-02 では生地マス数を注文個数に連動させていたが、「評価が上がって客が増えると台の見た目が賑やかになる」という繁盛具合の表現を優先する方針に変えた。生地マス数は「常時流している量」であり、いま対応中の客の注文個数とは独立した概念になる。

### 根拠

12 / 18 / 24 はいずれも `StandColumns`(6) の倍数で、**行単位で見た目が変わる**ため3段階を目視で判別しやすい。まず見た目の切り替わりを確認できることを優先した暫定値であり、演出確定時に見直す。

### 影響範囲

- `Unity/docs/.sdd/value-objects/03-takoyaki-stand-state.md`（§1 / §3 / §6 を改訂済み）
- `Unity/docs/.sdd/09-takoyaki-stand-view.md`（新規作成）
- [SV-14](./01-プロトコル契約の差分.md#sv-14)（`orderCount` の最大値）は、生地マス数が `orderCount` に依存しなくなったため**優先度が下がる**。ただし `TypedWordCount` が生地マス数を超え得るかの確認は依然必要

## D-03 — 評価の増減表示はサーバーイベント方式とし、クライアントで差分計算しない

- **日付**: 2026-08-04
- **決定者**: クライアント側の方針決定（**サーバー側の対応が必要**）
- **関連項目**: [SV-06](./01-プロトコル契約の差分.md#sv-06)

### 決定

1. 増減表示のトリガーは「評価が変わったタイミング」ではなく、**一定のタイミング**とする
2. 表示するのは増減量ではなく、**上がったか下がったかの方向**
3. この判定は**サーバーがイベントとして発行**する。クライアントは受け取って表示するだけ
4. **クライアント側で `EvaluationUpdate` の差分を取る実装は行わない**
5. 該当イベントが Proto に未定義のため、型の確定までクライアント側は**保留**

### 背景

当初は「表示している評価値の差分をクライアントで取る」案を検討していた。

### 根拠

評価は EMA・JKバズ加点・クレーマー減点・他店変動によるパーセンタイル再計算が合流した値であり、**クライアントには増減の因果を自分の提供へ帰属させる手段がない**。サーバーがイベントで方向を通知する方式にすることで、クライアントは一切の評価計算を持たずに済み、サーバー権威の原則（[docs/rules/01](../rules/01-責務と絶対原則.md)）とも完全に整合する。

### 影響範囲

- `Unity/docs/.sdd/value-objects/05-rank-bar-and-eval-delta-view-state.md` §4（保留として記載済み）
- Proto へのイベント追加依頼が必要

## D-02 — たこ焼き台は6列×4行＝24穴の横長グリッド

- **日付**: 2026-08-04
- **決定者**: クライアント側（**[SV-14](./01-プロトコル契約の差分.md#sv-14) でサーバー確認が必要**）
- **関連項目**: [SV-14](./01-プロトコル契約の差分.md#sv-14)

### 決定

たこ焼き台は **6列×4行＝24穴**の横長グリッド。各穴は `Empty`（なにもない）／`Batter`（生地・未クリア）／`Cooked`（焼けた・提供待ち）の3状態を持つ。

生地を流す穴の数は `min(orderCount, 24)`、焼けた穴の数は `min(typedWordCount, 生地を流した数)`。

### 背景

注文個数と台の物理的な穴数は別概念であり、注文個数によって生地を流す数が変わる。余った穴は `Empty` のまま残る。

### 根拠

用語集4章の注文個数（4/6/8/12）はいずれも24未満のため、**現行パラメータでは台からあふれるケースが発生しない**。クランプは将来の防御として残す。

### 影響範囲

- `Unity/docs/.sdd/value-objects/03-takoyaki-stand-state.md`（作成済み）
- `orderCount` の上限がサーバー側で保証されるかは未確認（[SV-14](./01-プロトコル契約の差分.md#sv-14)）

## D-01 — 店の評価3段階（緑/黄/赤）は相対順位の表示とする

- **日付**: 2026-08-04
- **決定者**: クライアント側（サーバー調整不要）
- **関連項目**: [SV-20](./02-パラメータと閾値.md#sv-20)

### 決定

店の状態を表す緑/黄/赤の3段階は、**絶対的な巧拙ではなく「今この試合での相対順位」**を表す。「赤＝下手」ではなく「赤＝現在下位グループにいる」を意味する。

### 背景

`evalNormalized` は用語集5章の定義通り「生存店内でのパーセンタイル(0..1)」であるため、固定閾値を引くと**全店の実力に関わらず常に一定割合が各帯に振り分けられる**。この性質を問題として扱うか、意図した仕様とするかの判断が必要だった。

### 根拠

下位淘汰（`ForcedElimination`）が正規化評価の下位を刈る仕様（用語集9章）であるため、相対順位の表示にしておくと**表示の意味と淘汰の危険度が一致する**。

### 影響範囲

- `Unity/docs/.sdd/value-objects/01-store-visual-state.md`（作成済み）
- 閾値の具体値は未確定（[SV-20](./02-パラメータと閾値.md#sv-20)）。赤帯の下限を `stormThresholdPct` と揃える案を候補として記載済み
