## A. Proto: C# ミラーに `displayName` を追加

### 対象ファイル

```
Takoda99-Proto / csharp/Takoda99.Proto/Messages.cs
```

### 現状（v0.3.0）

Go 正典にはあるが、C# ミラーに無い。コミット `d567a98`（2026-08-04）が Go のみを変更し、v0.3.0 で拾われなかったもの。

```csharp
// csharp/Takoda99.Proto/Messages.cs — 「C2S メッセージ」節、OrderServed の直後
public sealed class MatchmakingJoin { }      // ❌ フィールドが無い

public sealed class MatchmakingLeave { }
```

```go
// proto/messages.go（Go 正典）
type MatchmakingJoin struct {
    DisplayName string `json:"displayName,omitempty"`   // ✅ こちらが正しい
}
```

### 変更後（推奨する形）

```csharp
public sealed class MatchmakingJoin
{
    [JsonPropertyName("displayName")] public string DisplayName { get; set; } = "";
}
```

**この形を推す理由**：同ファイル内の他の文字列フィールド（`MatchStart.matchId` / `selfStoreId`、`StoreSummary.displayName` 等）がすべて `= ""` 初期化＋無条件シリアライズで書かれており、**ミラー内の書き方が揃う**。

### `omitempty` の扱いについて（判断は Proto 側にお任せします）

Go の `omitempty` は「空文字なら出力しない」ですが、**C# にこれと厳密に一致する指定はありません。**

| 指定 | 省略される条件 | Go の `omitempty` と一致するか |
|---|---|---|
| 指定なし（推奨） | 省略しない | ✕（ただし実害なし・後述） |
| `JsonIgnoreCondition.WhenWritingNull` | `null` のとき | ✕（`""` は出力される） |
| `JsonIgnoreCondition.WhenWritingDefault` | `default(string)` ＝ `null` のとき | ✕（同上） |

**実害が無いと考える理由**：`{"displayName":""}` と `{}` は、サーバーから見てどちらも「名前なし」でフォールバック名が割り当たる扱いのはずです（`awaitJoinName` の挙動としてそう理解しています）。**この理解が誤っていれば教えてください。**「空文字とキー欠落を区別している」場合は指定を変える必要があります。

### 同時に確認していただきたいこと

- **TS ミラー（`ts/types.ts`）にも同じ追従漏れがあります。** ただし takoda99-unity は C# しか使わないため、**要否の判断は Proto 側にお任せします**（こちらからは依頼しません）
- 3言語を揃える運用（AGENTS §2）に従うなら、この機会に TS も揃えるのが自然だと思われます

## B. サーバー: 表示名の最大長を 24 → 6 文字へ

### 変更内容

**プレイヤーが入力した表示名の正規化における最大長を、24文字から6文字へ変更してください。**

### 変更する理由（クライアント側の事情）

マッチング画面に参加者一覧（**縦9×横11＝99枠**）を置く設計にしました。1枠あたりの幅が狭く、**24文字は物理的に収まりません。**

クライアント側の入力欄には既に `characterLimit = 6` を掛けていますが、**これは自分の名前にしか効きません。** 他プレイヤーが別クライアントや直接接続で長い名前を送った場合、こちらの画面が崩れます。**正規化はサーバーが行うもの**（[SV-11](./01-プロトコル契約の差分.md#sv-11)）という取り決めに従い、サーバー側で6文字に揃えていただきたいです。

### 具体的な要件

1. **6文字を超える入力は6文字に切り詰める**（従来の24文字と同じ「切り詰め」の挙動で、値だけを変更）
2. **文字数の数え方を教えてください。** 「6文字」が
   - Unicode コードポイント数なのか
   - UTF-8 バイト数なのか
   - Go の `len([]rune(s))` なのか

   絵文字や結合文字（👨‍👩‍👧 等）で数え方が割れます。**クライアント側の `TMP_InputField.characterLimit` は UTF-16 コードユニット数で数える**ため、サーバーと完全一致はしません。**サーバーの数え方が正**とし、こちらは入力補助として近い値を掛けるだけにします
3. 制御文字の除去など、他の正規化は**従来どおりで構いません**

> **クライアント側では受信した名前を切り詰めません。** サーバーが正規化した結果をそのまま表示します（勝手に加工するとサーバーの正規化結果と画面が食い違うため）。溢れた場合は TMP の省略表示で受けます。

## C. サーバー: フォールバック名も6文字以内にし、書式を共有する

### 変更内容

**名前が空・未送信だったプレイヤーへ割り当てるフォールバック名と、定員補完の Bot 名も、6文字以内にしてください。**

### 変更する理由

B で入力名を6文字にしても、**フォールバック名と Bot 名が長いままだと結局レイアウトが崩れます。** しかも崩れるのは「名前を入力しなかった人」「Bot」だけなので、**テストで気付きにくく、本番の会場で初めて出る**種類の不具合になります。

### 具体的な要件

1. フォールバック名を**6文字以内**に
2. Bot 名を**6文字以内**に
3. **書式を教えてください。** 例えば `Player12`（8文字）のような形式だと6文字を超えます。`P12` `店12` `ゲスト1` 等、実際に割り当てる書式を共有していただければ、こちらの表示幅の設計に反映します

> **フォールバック名をクライアント側で生成することはしません**（[02-display-name.md](../../Unity/docs/.sdd/matchmaking/02-display-name.md) §1「他店の表示名をクライアントで生成・補完しない」）。必ずサーバーが値を配る前提で組みます。
