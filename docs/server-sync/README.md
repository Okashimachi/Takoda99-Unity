> **このディレクトリの位置づけ**
> [docs/rules/](../rules/README.md) が「このリポジトリでの作業ルール（守るもの）」であるのに対し、ここは「**まだ決まっていないこと・上流に持ち込むこと**」を置く。

## 2. ステータスの表記と運用

各項目の先頭に**状態**を1つ持たせる。**議論が進んだらこの1行を書き換えるだけ**で状態が切り替わるようにしている。

| 表記 | 意味 | 次にすること |
|---|---|---|
| 🔴 未確定 | 論点として認識しているが、まだサーバー側へ投げていない | サーバー担当へ共有する |
| 🟡 確認待ち | こちらの案・質問を提示済み。回答待ち | 回答を待つ／リマインドする |
| 🟢 確定 | 合意済み | [03-決定ログ.md](./03-決定ログ.md) へ転記し、上流と各 `.sdd` 仕様書へ反映する |
| ⚪ 対応不要 | 議論の結果、対応が不要になった | 理由を書いて残す（消さない） |

### 運用ルール

1. 項目には**安定した ID**（`SV-01` 等）を付ける。PR や会話から参照するため、**一度振った ID は再利用も欠番の詰め直しもしない**。
2. 状態を変えるときは、項目内の「状態」行と、各ファイル先頭の一覧表の両方を書き換える。
3. 🟢 確定にしたら、**必ず** [03-決定ログ.md](./03-決定ログ.md) に日付・決定内容・根拠を追記する。項目本体は消さず、「決定」欄を埋めて残す。
4. 決定が `.sdd` 仕様書に影響する場合、**仕様書の修正が完了するまで項目を閉じない**（「反映先」欄で追跡する）。
5. 契約（メッセージ・型）の変更が必要な結論になった場合、**このリポジトリでは実装しない**。Proto 側へ依頼する（[01-責務と絶対原則.md](../rules/01-責務と絶対原則.md)）。
