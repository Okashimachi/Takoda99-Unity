## SV-01

**状態**: 🔴 未確定
**題目**: `EvaluationUpdate` に `storeId` が無く自店専用

### 事実（Proto）

```csharp
public sealed class EvaluationUpdate
{
    public double EvalRaw { get; set; }
    public double Normalized { get; set; } // 0..1
    public int Rank { get; set; }
    public int AliveCount { get; set; }
}
```

`storeId` を持たないため、このメッセージは**自店の評価のみ**を運ぶと解釈される。`CreditUpdate` も同様に `storeId` を持たない（`life` / `delta` / `reason` のみ）。

### 論点

他店（99店ミニ盤面）の評価・信用は `StoreListUpdate`（`List<StoreSummary>` のフルスナップ）でしか取得できないことになる。この理解で正しいか。

### クライアント側への影響

**本リポジトリの仕様書に誤りがある。** [pureC#/docs/.sdd/value-objects/02-store-state.md](../../pureC%23/docs/.sdd/value-objects/02-store-state.md) は「`EvaluationUpdate` の対象 `StoreId` が自店なら `StoreState`、他店なら `StoreSummaryState` を更新」と書いているが、Proto 上そのような分岐は成立しない。正しくは:

- `EvaluationUpdate` / `CreditUpdate` → 自店の `StoreState` のみ更新
- `StoreListUpdate` → 全店の `StoreSummaryState` を一括置換

### 決めたいこと

1. 上記の理解で正しいか
2. 正しい場合、他店の評価更新の粒度は `StoreListUpdate` の頻度に完全に依存する（→ [SV-02](#sv-02)）

### 決定

## SV-03

**状態**: 🔴 未確定
**題目**: 我慢ゲージ残量を同期するメッセージが存在しない

### 事実（Proto）

- `CustomerView`（`CustomerArrived` のペイロード）は `patienceMaxMs` のみを持つ
- **`patienceLeftMs` を運ぶメッセージは存在しない**
- 客が離脱したことは `CustomerLeft`（`customerId` / `reason: Timeout`）で事後的に届く

つまり現契約では、クライアントは `patienceMaxMs` から**ローカルにカウントダウンし、`CustomerLeft` が来たら離脱として扱う**以外の実装ができない。

### 論点

用語集7章は「我慢ゲージの確定はサーバー権威、クライアントは表示専用カウントダウン」としており、契約はこの方針と整合している。一方で、以下が保証されないと表示とサーバー実態がズレる。

- 終盤短縮係数 `patienceLateMul`（用語集8章）が適用されると、サーバー側の残り時間は縮むが、クライアントは `patienceMaxMs` 基準で数え続けてしまう
- ネットワーク遅延・タブ非アクティブ（WebGL）でクライアントのカウントが遅れる

### 決めたいこと

1. 我慢ゲージのローカルカウントダウンで運用する前提でよいか
2. 終盤短縮が入ったとき、クライアントへどう伝えるか（`patienceMaxMs` を短くした新しい値を送り直す／短縮係数を配信する／伝えない）
3. クライアントの表示が0になっても `CustomerLeft` が来ない場合の扱い（0で止めて待つ、で問題ないか）

### クライアント側の現状の想定

[Unity/docs/.sdd/value-objects/02-customer-mood-state.md](../../Unity/docs/.sdd/value-objects/02-customer-mood-state.md) では、表示が0に達した時点で `TurnedAway`（退転演出）に入り、**行列からの実除去は `CustomerLeft` 受信まで待つ**設計にしてある。この方針で問題ないかの確認を含む。

3. 他店の行列長を表示する予定はあるか（現状 `StoreSummary` に含まれない）

## SV-05

**状態**: 🔴 未確定
**題目**: `ForcedEliminationWarning.untilTick` が解釈できない

### 事実（Proto）

```csharp
public sealed class ForcedEliminationWarning
{
    public int UntilTick { get; set; }
    public double ThresholdPct { get; set; }
}
```

`untilTick`（あと何 tick で下位淘汰か）を受け取るが、**クライアントは tick の長さ（`tickIntervalMs`）も現在の tick 番号も受信していない**。`GameParametersPublicSubset` にも含まれない（`matchTimeLimitMs` / `initialLife` / `maxStores` のみ）。

1. `tickIntervalMs` を `GameParametersPublicSubset` に追加する（クライアントが ms 換算する）
2. `ForcedEliminationWarning` のフィールドを `untilMs` に変更する（最も単純）
3. 予告は「もうすぐ来る」という定性的表示に留め、残り時間を出さない

### 事実（Proto）

評価の増減（上がった / 下がった）を通知するメッセージは存在しない。`EvaluationUpdate` は現在値のみを運ぶ。

### 論点

画面上の「★+0.2」相当の表示について、**一定のタイミングで評価が上がったか下がったかをサーバーがイベントで発行する**方針を決定済み（[03-決定ログ.md](./03-決定ログ.md) の D-03）。該当イベントが Proto に無いため、契約追加の依頼が必要。

### 決めたいこと

1. イベントの発行間隔（固定周期か、提供に紐づくか）
2. ペイロード（方向のみか、増減量も含むか）
3. 対象（自店のみか、他店も含むか）

**題目**: 再接続・途中復帰時の状態再同期手段が無い

### 事実（Proto）

- `MatchStart` は試合開始時の1回のみを想定した内容（`selfStoreId` / `params` / `phase` / `stores`）

3. WebGL でタブが非アクティブになり WebSocket が維持されないケースの扱い

## SV-10

**状態**: 🔴 未確定
**題目**: 自店専用メッセージと全体配信メッセージの区別の明文化

### 事実（Proto）

`storeId` の有無で、メッセージが自店専用か全店対象かが暗黙に分かれている。

| 区分 | メッセージ |
|---|---|

### 決めたいこと

上記の理解が正しいことの確認と、プロトコル仕様書（`Takoda99-Docs/02_共通仕様/02_プロトコル仕様.md`）への明記の可否。

## SV-13

**状態**: 🔴 未確定
**題目**: `missCount` の集計粒度と `SanityCheck` の下限

### 事実（Proto）

```csharp
public sealed class OrderServed
{
    public string CustomerId { get; set; }
    public int ElapsedMs { get; set; }
    public int MissCount { get; set; }
    public long ClientTimestamp { get; set; }
}
```

`missCount` の**数え方**は契約に書かれていない。

### 論点

用語集4章は「精度 = `1 - (missCount / 総打鍵)`」としているが、`OrderServed` は総打鍵数を送っていない。サーバーは `orderCount` と単語長から総打鍵数を推定していると思われる。

また、以下で値が変わる。

- 1文字ミスするたびに +1 なのか、1単語につき最大1回なのか
- ローマ字入力で複数パターンがある文字（`shi`/`si` 等）の途中入力をミスと数えるか

### 決めたいこと

1. `missCount` の定義（1文字ミスごとに +1 で確定してよいか）
2. サーバーの `SanityCheck`（用語集11章）が弾く下限値（`elapsedMs` の最小値等）。クライアントが正常な範囲を知らないと、正当なプレイが弾かれても気付けない

### クライアント側の現状の想定

[pureC#/docs/.sdd/value-objects/04-order-progress-state.md](../../pureC%23/docs/.sdd/value-objects/04-order-progress-state.md) では「1文字ミスごとに +1」を仮置きし、未確定事項として残している。
