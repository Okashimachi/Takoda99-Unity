# 02-お題の大型化と枠外飛び出し演出

> 参照する上流：[本選企画書 3.4](https://github.com/Okashimachi/Takoda99-Docs/blob/main/00_本選差分/01_本選企画書.md)（お題の枠を「演出として意図的に採用」）／[12_差分_クライアント §2.2](https://github.com/Okashimachi/Takoda99-Docs/blob/main/00_本選差分/12_差分_クライアント.md)／既存 [match-view/02-main-store-view.md](../match-view/02-main-store-view.md)。矛盾したら上流優先。

## 0. 背景

予選のフィードバックで最も多かったのが **「お題しか見られない」**。本選はこれを直そうとするのではなく、**お題が主役であることを認めて、他の情報を減らした**。空いた面積をお題に使う。

予選で「文字が枠を飛び出すバグ」だったものは、**体力表示の制約が消えたことで演出として成立するようになった**ため、意図的に採用する。

## 1. 責務

**する**

- お題単語を予選より**大きく**描く
- 単語長に応じて枠を超えて広がる表示を、**破綻せずに**成立させる
- 打鍵の進捗（確定済み／未確定／ミス）の描き分けを維持する

**しない**

- お題単語を生成・加工しない（サーバー発行の `CustomerView.Words[]` をそのまま使う）
- 打鍵の正誤を判定しない（`ITypingJudge.CurrentView` の値を描くだけ）

## 2. 描画の供給元（変更なし）

```csharp
var view = typingJudge.CurrentView;
mainStore.SetWord(view.CurrentWord, view.CurrentRoma);
mainStore.SetTypedProgress(view.TypedKanaLength, view.TypedRomaLength);
```

既存 [match-view/01-renderer.md](../match-view/01-renderer.md) の `ApplyWord` の規則をそのまま維持する：

> `CurrentOrder` が先頭客とまだ一致していない間は**空欄にする**。注文カウンタの分母が新しい客に切り替わっているのに前の客のお題が残ると、食い違った組が一瞬出る。

**この規則は本選でも消さない。** 客の離脱がなくなっても、「前の客の提供完了 → 次の `CustomerArrived` 到着」の隙間は依然として存在する。

## 3. 大型化の要件

| # | 要件 |
|---|---|
| W1 | 短い単語（2〜3文字）で**最大サイズ**になり、画面の主役として成立すること |
| W2 | 長い単語でも**読めること**が最優先。飛び出し演出のために可読性を落とさない |
| W3 | かな行とローマ字行の**対応が崩れないこと**（どこまで打ったかが見えなくなる状態を作らない） |
| W4 | 縦画面の横幅が最も厳しい制約。**横方向にはみ出させる場合、両端が切れて読めなくならないこと** |

### 3.1 サイズの決め方

TextMeshPro の **Auto Size を使わない**。単語長から段階的に決める。

```
文字数 1..3   → サイズ L（最大）
文字数 4..6   → サイズ M
文字数 7以上  → サイズ S
```

| 理由 | 内容 |
|---|---|
| Auto Size は毎フレーム再レイアウトが走る | お題は打鍵1回ごとに `SetWord` / `SetTypedProgress` が呼ばれる。WebGL で効く |
| 段階制なら**同じ長さの単語が常に同じ大きさになる** | 単語が変わるたびに微妙にサイズが動くのは、読む側の負担になる |

段階の閾値と実サイズは Inspector 公開値にして、実機で詰められるようにする。

### 3.2 枠外への広がり

「枠」＝ お題の背景パネル。**テキストは枠の子にするが、`RectMask2D` / `Mask` を掛けない。**

| 要素 | 扱い |
|---|---|
| 背景パネル | 固定サイズ。ここが「枠」の見た目 |
| かな行テキスト | 枠の外へはみ出してよい。**中央揃え**（左右対称にはみ出すので W4 を満たしやすい） |
| ローマ字行テキスト | 同上。かな行と同じ中央基準で揃える |
| セーフエリア | 画面端から一定マージンを確保し、**そこは超えない**。超える長さならサイズ段階を1つ下げる |

> **マスクを掛けないことがこの演出の実装のすべて。** 予選で「バグ」だったのはマスクが無いまま枠を超えていた状態であり、本選ではそれを正とする。追加で必要なのは「画面端は超えない」保証だけ。

## 4. 演出（任意・優先度は配置より下）

| 契機 | 演出 |
|---|---|
| 新しいお題の表示 | 出現時に軽くスケール（DOTween）。**打鍵の受付を遅らせない**（演出中も入力は通す） |
| 1単語打ち切り（`WordCleared`） | 打ち切った単語を弾けさせて次へ |
| ミス打鍵 | 短い横振動。**0.1秒以内**に収める（連続ミスで画面が揺れ続けない） |

| 禁止 | 理由 |
|---|---|
| 演出中に入力を止める | 打鍵ゲームで最もやってはいけないこと |
| 演出の完了を待って次の単語を出す | 速い人ほど演出待ちで損をする |

## 6. テスト観点

| # | 観点 | 方法 |
|---|---|---|
| 1 | 1文字・3文字・6文字・12文字の単語でサイズ段階が切り替わる | `MainGameViewSampleDriver` に各長さのサンプルを入れて目視 |
| 2 | 最長級の単語で**画面端を超えない** | 同上（縦画面の実解像度で確認） |
| 3 | かな行とローマ字行の打鍵位置がずれない | 打鍵して目視 |
| 4 | 演出中も打鍵が取りこぼされない | 高速に連打して `OrderServed` の `missCount` が増えないこと |
| 5 | 前の客の提供完了直後に、前の単語が残らない | 目視 |
