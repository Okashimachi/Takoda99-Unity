# 02-RomajiTable（ローマ字テーブルとかな分割）

> 参照する上流：[Takoda99-Client-Docs 第6章 §2・§2.1・§6.1](https://github.com/Okashimachi/Takoda99-Client-Docs/blob/main/06_打鍵判定共通仕様.md)。サーバー側の正準打鍵数は [Takoda99-Server](https://github.com/Okashimachi/Takoda99-Server) `internal/odai/romaji.go`。矛盾したら上流優先。

## 1. 責務

**する：**
- 「かな → 受理するローマ字パターン集合」の**データ提供**。
- お題単語を**かな単位（打鍵単位）に分割**する（最長一致）。
- 促音「っ」・撥音「ん」の**文脈依存パターンを解決**して、後続の [03-typing-judge](./03-typing-judge.md) が「前方一致で辿るだけ」で済む形に落とす。

**しない：**
- 打鍵の受理判定そのもの（→ [03-typing-judge](./03-typing-judge.md)）。
- `missCount` / `elapsedMs` の計測（→ 03）。
- **テーブルデータの独自定義を正典化しない。** 正典は Proto の共有データ。Proto 未投入の間だけ暫定テーブルを置く（[docs/rules/01](../../../docs/rules/01-責務と絶対原則.md) 絶対原則2）。

## 2. 公開インターフェース

```csharp
namespace Takoda99.Client.Typing;

/// <summary>打鍵単位（かな1つ、または非かな文字1つ）と、その受理ローマ字候補。</summary>
public readonly struct KanaUnit
{
    /// <summary>元のかな表記（"た" / "しゃ" / "っ" / "ん" / "ー" / "a"）。表示のハイライト幅に使う。</summary>
    public string Kana { get; }

    /// <summary>この位置で受理するローマ字パターン（文脈解決済み）。すべて小文字。</summary>
    public IReadOnlyList<string> Patterns { get; }
}

/// <summary>
/// ローマ字テーブル。正典は Proto 共有データで、実装はその差し替え口。
/// ハードコードしたテーブルを判定ロジック側に埋め込まないための境界（第6章 §2）。
/// </summary>
public interface IRomajiTable
{
    /// <summary>最長一致で探索するかなの最大文字数（拗音を含むので通常 2）。</summary>
    int MaxKanaLength { get; }

    /// <summary>単一かなの受理パターン（文脈解決前の素の値）。未登録なら空。</summary>
    IReadOnlyList<string> GetPatterns(string kana);

    /// <summary>
    /// お題単語を打鍵単位へ分割し、促音・撥音の文脈を解決した候補付きで返す。
    /// </summary>
    /// <remarks>未登録のかなが現れても例外を投げず、その1文字をそのまま1打鍵単位として返す。</remarks>
    IReadOnlyList<KanaUnit> Segment(string word);
}
```

> **設計判断**：促音・撥音の文脈解決を**テーブル側（`Segment`）に置く**。第6章 §2 が特殊処理をテーブルの責務として挙げており、こうすると 03 のオートマトンは「候補集合を前方一致で辿るだけ」の単純な形に保てる（＝テストしやすい）。

## 3. ふるまいの詳細

### 3.1 分割（`Segment`）
- **最長一致**：`MaxKanaLength` 文字から順に短くして探索する（`しゃ` を `し`+`ゃ` に割らない）。
- **非かな文字**（英数字・記号）：1文字＝1打鍵単位とし、`Patterns` はその文字自身（小文字化）1件。
- 未登録のかな：例外にせず、その1文字を単位として通す（判定不能なお題でクラッシュさせない）。

### 3.2 促音「っ」の文脈解決
| 次の単位 | 受理パターン |
|---|---|
| 子音で始まる（例 `こ`→`ko`） | **次の子音の重ね**（`k`）＋ `xtu` / `ltu` / `ltsu` / `xtsu` |
| 母音で始まる／語末 | `xtu` / `ltu` / `ltsu` / `xtsu` のみ（子音重ねは不可） |

- 例：`たっこ` → `takko` も `taxtuko` も受理（第6章 §6 テスト表）。

### 3.3 撥音「ん」の文脈解決
| 次の単位 | 受理パターン |
|---|---|
| 母音・な行・「ん」・語末 | `nn` / `xn` / `n'`（**`n` 単独は不可**） |
| それ以外の子音 | `n` / `nn` / `xn` / `n'` |

- 例：`かんい` → `kanni` は受理、`kani` は不可（第6章 §6 テスト表）。

### 3.4 その他
- 伸ばし棒「ー」→ `-`。
- パターンは**すべて小文字で保持**する（大文字小文字の同一視は 03 が入力側を小文字化して行う）。
- **正準表記を必ず含める**：サーバーが打鍵数を数える最短系（`し=si` / `ち=ti` / `つ=tu` / `ふ=hu` / `じ=zi` / `しゃ=sya`）を候補から落とさない。

### 3.5 暫定テーブルの扱い
- Proto 未投入の間は `DefaultRomajiTable`（暫定データ）を `IRomajiTable` の実装として置く。
- **暫定である旨をクラスの XML ドキュメントコメントに明記**し、Proto 投入時にこのクラスだけを差し替えれば済む状態を保つ。判定ロジック（03）は `IRomajiTable` にのみ依存する。

## 4. 依存関係

- 依存するモジュール：なし（将来 Proto の共有データを読む）
- 依存されるモジュール：[03-typing-judge](./03-typing-judge.md)
- `Takoda99.Proto` の DTO には依存しない（テーブルはメッセージ契約ではないため）

## 5. テスト観点

| # | ケース | 期待 |
|---|---|---|
| 1 | `たこ` の分割 | `[た, こ]` の2単位 |
| 2 | `きゃ` の分割 | `[きゃ]` の1単位（`き`+`ゃ` に割らない） |
| 3 | `し` のパターン | `si` / `shi` / `ci` を含む |
| 4 | `がっこう` の `っ` | `k` を含む（`gakkou` が成立する） |
| 5 | `たっち` の `っ` | `t` を含む（`tatchi` 系。次子音に追随する） |
| 6 | 語末の `っ` | `xtu` 系のみ、子音重ねを含まない |
| 7 | `かんい` の `ん` | `nn` を含み `n` 単独を**含まない** |
| 8 | `かんじ` の `ん` | `n` を含む |
| 9 | `ー` | `-` |
| 10 | 英数字混じり | 1文字1単位、パターンは自身 |
| 11 | 未登録のかな | 例外にならず1単位で返る |
| 12 | 全パターンが小文字 | 大文字を含まない |
| 13 | 正準表記の網羅 | `si/ti/tu/hu/zi/sya` が各かなの候補に含まれる |

## 6. 未確定事項

- **Proto へのテーブル投入時期とデータ形式**（第6章 §9）。投入されたら `DefaultRomajiTable` を差し替え、上の全テストが通ることを確認する。形式変更が要るなら Proto の人間承認フローへ。
- 記号・数字混じり単語の扱い（サーバーの出題方針が確定してから）。
- `n'`（アポストロフィ）を受理するか（打ちにくく実用性が低いなら候補から外す判断もある）。
